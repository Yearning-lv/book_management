# 演示案例与答辩流程

## 一、建议演示顺序

1. 先运行根目录的 `reset-demo-data.cmd`，把数据库恢复到演示初始状态。
2. 双击 `start-library.cmd` 启动前后端。
3. 依次演示管理员、工作人员、读者三类角色。

## 二、演示账号

- 管理员：`admin / 123456`
- 工作人员：`staff01 / 123456`
- 工作人员：`staff02 / 123456`
- 读者：`reader01 / 123456`
- 读者：`reader02 / 123456`
- 读者：`reader03 / 123456`
- 读者：`reader04 / 123456`
- 读者：`reader05 / 123456`
- 读者：`reader06 / 123456`
- 读者：`reader07 / 123456`
- 读者：`reader08 / 123456`

## 三、管理员演示点

1. 登录 `admin`，进入“账户管理”。
2. 说明管理员只负责工作人员和读者账户，左侧菜单没有图书流通操作。
3. 在账户列表中展示：
   - `staff01`、`staff02` 两个工作人员账号
   - `reader01 ~ reader08` 多个读者账号
4. 选择 `reader02`，展示其存在未结清罚金余额。
5. 选择 `reader08`，展示其借阅证状态为 `PAUSED`。
6. 新增一个测试读者或工作人员，证明管理员可以维护账户。
7. 切到“统计分析”，展示：
   - 图书种类、馆藏副本、读者规模
   - 在途借阅、逾期记录、预约队列
   - 分类分布、近 6 个月借阅趋势、热门图书 TOP 5

## 四、工作人员演示点

1. 登录 `staff01`，确认左侧只有“图书目录、馆藏副本、借阅中心、统计分析”。
2. 在“图书目录”中演示：
   - 查询图书
   - 查看 `创新管理实践` 为 `OFF_SHELF`
   - 修改一本图书信息并保存
3. 在“馆藏副本”中演示：
   - 不同副本状态：`AVAILABLE`、`BORROWED`、`RESERVED`、`REPAIR`、`LOST`
   - 新增或编辑一个副本
4. 在“借阅中心”中演示正常借书：
   - 给 `reader05` 借出可用副本，例如 `BC20260003`
5. 演示归还触发预约：
   - 当前 `reader07` 借有《数据可视化实战》
   - 归还该记录后，`reader05` 的预约会从 `WAITING` 变为 `READY`
   - 图书副本状态会转为 `RESERVED`
6. 演示预约取书：
   - 当前 `reader04` 对《数据结构与算法分析》已有 `READY` 预约
   - 工作人员可直接把 `BC20260004` 借给 `reader04`
7. 演示借阅失败校验：
   - 给 `reader03` 再借一本书，会提示“已达到借阅上限”
   - 给 `reader02` 借书，会提示“存在未结清罚金”

## 五、读者演示点

1. 登录 `reader01`，确认左侧没有“账户管理”。
2. 在“图书目录”中搜索图书，展示读者只能检索和预约。
3. 在“借阅中心”中展示：
   - 只能看到自己的借阅记录
   - 当前有一条可续借记录《Java核心技术 卷I》
4. 点击“续借”，演示个人续借成功。
5. 切到预约页，可对无可借副本的图书发起预约，例如《数据库系统概论》。
6. 使用 `reader05` 或 `reader06` 登录，演示取消自己的预约。
7. 使用 `reader02` 登录，展示逾期记录与欠费场景。

## 六、适合回答老师追问的亮点

- 三角色权限严格分离，菜单和接口都按角色控制。
- 借阅流程不是简单增删改查，而是包含预约排队、待取、借出、续借、逾期、归还、罚金。
- 演示数据采用多场景设计，导入后即可直接展示正常流程与异常校验。
- 提供了 `reset-demo-data.cmd`，误操作后可一键恢复到初始演示状态。
